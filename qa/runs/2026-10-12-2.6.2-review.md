# 2.6.2 review pass - 2026-10-12

Code-flow and browser review of every 2.6.2 change (Free and Pro, branch `2.6.2`,
diff against `v2.6.1`), run by the developer after the last fix batch. QA
verdicts stay with QA: the fixes are on Basecamp card 10393752949 (Ready for
Testing), next to six earlier 2.6.2 cards.

**Build:** wpmediaverse `ee4caebd`, wpmediaverse-pro `4634988`. Local CI
(`bin/local-ci.sh --no-journeys`) green on both. Migrator 43.

**Sites:** mediaverse.local (MySQL 8.4, nginx, model site) and the Docker
wp-env `mvs-qa-262` (MariaDB 12, Apache, Reign, BuddyPress). Both were upgraded
from 2.6.1 and both ran Migrator v42 and v43.

## Method

- Three read-only code reviews, one per area: visibility and listings;
  messaging, erasure, notifications and email; uploads, albums, documents, Pro
  and frontend. Every reported finding was re-checked in code before acting.
- Browser audit: each screen loaded in a same-origin iframe at 1440, 820 and
  390. It measures page overflow, MediaVerse elements past the edge, broken
  images, targets under 24px (44px for buttons at tablet widths) and console
  errors. Run as visitor, member and owner on both sites, with Twenty
  Twenty-Five on Docker and dark mode on mediaverse.local.

## Findings and fixes

| # | Area | Finding | Introduced | Fix |
|---|------|---------|------------|-----|
| 1 | Chat files | The legacy move deleted a sent attachment whose file was not readable locally (offloaded storage), and an unsent one minutes old | 2.6.2 | Sent and unreadable: `fail()`, kept hidden, shown in Site Health. Unsent: removed only past `mvs_unsent_chat_file_hours` |
| 2 | Account deletion | A second request while one was pending recorded the deletion's own suspension as the member's, so Cancel left them suspended | 2.6.2 | `request()` changes nothing while a deletion is scheduled |
| 3 | Email | Challenge emails were suppressed on BuddyNext sites, and BuddyNext does not send them | 2.6.2 | `EmailService::host_owns()`; per-type `host_owned` (Pro challenge types `false`). Settings > Emails lists only non-host emails on host sites |
| 4 | Competitions | "Upload a new photo" took the site's default privacy, but entries must be public | 2.6.2 | Upload asks for public; the picker lists public photos only; the member is told when the owner's lock keeps it non-public; outdated notice removed |
| 5 | Galleries | The Media Grid block kept its own old gallery subquery | missed sibling | Uses `gallery_hidden_clause()` |

## Checked and clean

- Visitor and member screens on both sites at all three widths: no page
  overflow, no broken images, no console errors other than the audit's own
  probes. The strips past the edge (tag cloud, dashboard tabs, competition
  tabs) are deliberate scrollers.
- Twenty Twenty-Five: MediaVerse controls keep their own styling.
- Dark mode: the challenge entry panel reads correctly.
- Confirmed not defects: the 32px chat header buttons and 38px Post button
  at 820 (the 44px floor applies under `pointer: coarse`, which an iframe in
  desktop Chrome does not report); the edge-to-edge social bar.

## Open

- **Not verified live:** a real BuddyNext site (switch simulated with a

  unused `search` parameter; its grid is never search-filtered.
