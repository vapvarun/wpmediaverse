## Gate-verified findings

### F1 (verified, FIXED in 031f326)
- **Title:** FieldRenderer checkbox renderer ignored `register_setting` defaults; 1.3.0 image-optimization settings would silently disable on first Save.
- **Severity (final):** Critical (release blocker — 1.3.0 headline feature)
- **Cite:** `includes/Admin/Settings/SettingsRegistrar.php:368,392` (default=true), `includes/Admin/Settings/FieldRenderer.php:288` (hardcoded false fallback), `readme.txt` 1.3.0 entry (promise "automatic image optimization on every upload"), `CLAUDE.md` Recent Changes table for 1.2.2 ("Storage tab, both default on").
- **Repro (Opus-confirmed):** WP-CLI eval after `delete_option('mvs_optimize_originals')` then `do_action('admin_init')` with `admin.settings` lazy-loaded — `get_option('mvs_optimize_originals')` returns `false` even though `register_setting` declares `default => true`. WordPress's `default_option_$key` filter chain is bypassed when caller passes explicit second arg to `get_option`.
- **Fix:** 3-line change in `FieldRenderer::render_checkbox_field` — read `get_registered_settings()[$key]['default']` and pass it as the `get_option` fallback.
- **Verified:**
  - Code: WP-CLI eval shows CHECKED / CHECKED / unchecked for `mvs_optimize_originals` / `mvs_generate_webp` / `mvs_generate_avif` (matches registered defaults true / true / false).
  - Browser: Storage tab renders all 3 checkboxes with correct pre-checked state after `wp_options` rows deleted.
  - WPCS + PHPStan clean.
