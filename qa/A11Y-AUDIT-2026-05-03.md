# Accessibility Audit — 1.2.0 RC

> **Date:** 2026-05-03
> **Scope:** all customer-facing surfaces in the Free plugin (lightbox, blocks, page templates, BP profile/group tabs).
> **Standard:** WCAG 2.1 AA — focus on perceivable + operable interactive elements.

## Summary

Pass-1 audit completed. All HIGH-traffic surfaces brought to a clean baseline. Two follow-up passes deferred to 1.2.1 (specifically the admin pages + Pro-side blocks).

## Deferred to 1.2.1 (still)

- **Color contrast audit** — verify WCAG AA contrast ratios against every theme that ships with the plugin (BuddyX, Reign, BuddyBoss). Lightbox dark backgrounds + muted text variants need spot-checks. Out of scope for code-level fixes.
- **Screen-reader live regions** — async state changes (upload progress, comment posted, download started) currently surface via toast messages. Need aria-live="polite" on the toast container so screen readers announce them. Quick fix candidate for 1.2.1.
- **Reduced-motion preference** — respect prefers-reduced-motion: reduce on the lightbox open/close transition, story bar animations, and any future CSS animations. Quick CSS-only addition for 1.2.1.

## Audit method

For each surface, ran:
1. `grep -rE '<button[^>]*>'` filtered for missing aria-label + missing visible-text-content.
2. `grep -rE '<input'` filtered for missing aria-label + missing associated <label>.
3. Lightbox interactive elements traced via the Interactivity API directives (data-wp-on--*) so every action handler has a known UI surface.
4. Browser devtools inspection — confirmed the live DOM at /mvs-test-blocks/ has the expected ARIA attributes after build.

The same pattern can be re-run as a CI guard once the audit cadence is set.
