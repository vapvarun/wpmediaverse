# 2.7.1 follow-ups

Found during 2.7.0 work and deliberately not changed in 2.7.0.

## Design option: grid hover stats on a bottom gradient

2.7.0 puts the grid tile's hover stats on the full-tile `--mvs-overlay` (0.72
black), which passes (9.29:1) but turns a hovered white photo flat #474747.
Option: a bottom gradient (transparent to `--mvs-overlay`) with the stats moved
to the bottom edge, so the picture keeps its look above the text. Measure the
stats against a white photo at the gradient's text position before choosing it.

## Twenty Twenty-Five dark mode was not exercised

Twenty Twenty-Five has no dark switch MediaVerse follows (no data attribute,
no class), so the 2.7.0 contrast pass covered it in light only.

## Third-party notice suppression never matches MediaVerse submenu pages

`assets/css/admin.css` hides third-party notices on MediaVerse screens with
`[class*="wpmediaverse_page"] .notice:not(.mvs-notice):not(.settings-error)` and
siblings (the "Suppress Third-Party Notices on MVS Pages" block, next to the
working `.toplevel_page_wpmediaverse` rules).

Evidence (buddynext.local, 2026-11-23): the body classes of the submenu screens
are `mediaverse_page_mvs-documents`, `mediaverse_page_mvs-tags`,
`mediaverse_page_mvs-theme-library`, `mediaverse_page_mvs-competitions` and
`mediaverse_page_mvs-settings`. WordPress builds the prefix from the menu title
("MediaVerse"), not the slug, so `wpmediaverse_page` never occurs and the rule
only works on the top-level screen (`toplevel_page_wpmediaverse`).

Why not fixed in 2.7.0: correcting the selector starts hiding other plugins'
notices on every MediaVerse submenu screen, a behaviour change for site owners.
Decide in 2.7.1 whether that is wanted, then match `[class*="mediaverse_page_"]`
(the same prefix the control-edge rule in `admin.css` already uses).

## Focus rings on a pale brand colour

The 2px focus ring is drawn in `--mvs-primary`. On a pale brand colour it
does not reach WCAG 1.4.11's 3:1 against a light card: QA measured 1.38:1 on
`#ffd34d` (MV34, 2026-11-23). The same class of problem was fixed in Jetonomy
with an accent ink. Owner cut it from 2.7.0 (release scope).

Option checked during 2.7.0 and not shipped: a `--mvs-focus-ring` token set to
`--mvs-primary-text` (`oklch(from var(--mvs-primary) min(l, 0.48) c h)`,
lightened in the dark block) and every brand ring routed through it. Measured
against white: `#ffd34d` 1.43 -> 6.49, `#ef5455` 3.46 -> 7.25, `#1d76da` 4.51
-> 6.6, `#2271b1` 5.17 -> 6.51. It needs one exception: the lightbox close,
fullscreen and arrow buttons sit on the dark media stage in both modes and
measured 2.83:1 with the darker ink, so they take `--mvs-on-overlay` instead.


## From QA MV36 and the 2.7.0 Free-only smoke (2026-11-24)

Not release blockers for 2.7.0. Numbers are as measured by QA or the smoke run.

- **BuddyX: reply quote inside a sent chat bubble** reads 3.61:1 light and 4.37:1 dark (QA MV36). The overlay is a fixed `rgba(0, 0, 0, 0.18)`; derive it from `--mvs-chat-on-fill` so it follows the fill the theme supplies.
- **Chat send button at rest** is drawn at `opacity: .5` but carries no `disabled` or `aria-disabled`, so a screen reader announces an active button that does nothing (QA MV36).
- **Adding 40 photos to an album** still costs about 503 queries (QA MV36). The tag-cloud clear is now once per burst; the rest is per-photo work in the add path.
- **Reign: no keyboard focus ring** on `.mvs-chat-trigger`, the chat tabs, the upload confirm and cancel buttons and the guest banner dismiss after a real Tab. BuddyX supplies its own ring, so the plugin relies on the theme. Ship a MediaVerse `:focus-visible` ring for these controls.
- **Chat panel at 390px:** the "Upload media" fab sits over the open chat panel's composer on /my-media/ and /explore-media/.
- **Chat field edges:** chat search input and composer textarea borders are 1.15-1.53:1 against the panel; use `--mvs-border-control` (3:1).
- **"Complete your profile" prompt:** amber text on its amber tint is 2.93:1 on Reign, 2.85:1 on BuddyX (text needs 4.5:1).
- **Free without Pro, Documents:** "Explore Documents" stays in the nav while /explore-document/ renders only its heading, and the admin note points to a Documents setting Free does not have.
- **Unread chat badge undercounts for up to 60s:** `NotificationListener::on_message_sent` skips clearing the unread cache when a second message lands inside the 30-second coalesce window (two messages 1s apart showed 1).
- **BuddyX:** lightbox "Post" button 4.46:1 light, 3.83:1 dark; focus ring 2.78:1 in dark.
- **Partial package:** with `libs/action-scheduler/classes` removed the site fatals, because Free checks only that `action-scheduler.php` exists (same in 2.6.4). The EDD SDK already degrades to a notice; give Action Scheduler the same completeness check.
