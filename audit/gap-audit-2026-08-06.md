## Still open — ranked

### P0

- **Messaging poll N+1.** `includes/Messaging/MessagingService.php:2769` (`poll_reaction_updates`)
  and `:2667` (`poll`) correctly `LIMIT 100`, then fire per-row reaction / attachment /
  media-share / preview queries inside the loop. At ~5s client polling, 200 open chats ≈ a
  sustained **~8,000 queries/sec floor**. This is load-driven, not row-count-driven — it is the
  finding most likely to take a healthy site down today.
- **`src/blocks/album-viewer/render.php:64`** — unbounded `SELECT idx.*` joined to
  `mvs_album_items`, then `get_permalink()` + `media_thumbnail()` per tile. 2000 items ≈ 28,000
  queries → `max_execution_time` fatal. Reachable from any page via `[mvs_album]`. The 1.7.0
  `prefetch()` fix reached every other grid but this one and
  `Integrations/BuddyPress/BaseBPTabIntegration.php:592`.
- **App has no offline layer.** Zero hits for `NetInfo` / `onlineManager` / `ErrorBoundary`;
  `api/queryClient.ts:11-18` has no `defaultOptions.mutations`, so **mutations retry zero
  times**. Offline, every screen spins ~40s before any feedback; any render throw is a white
  screen.

### P1

- `app/compose.tsx:189` — new post invalidates only `['media','feed']`; the profile grid reads
  `['me','media']`, so **your own new post never appears on your profile**.
- `app/media/[id].tsx:62-66` — delete misses `['media','gallery']`, `['media','item']`, and
  album/collection item keys. `app/edit-media/[id].tsx:76-78` documents exactly why that key
  matters.
- `app/onboarding/interests.tsx:41` + `follow.tsx:33` — both swallow save failures and advance;

- `api/upload.ts:67` — gallery uploads send `media_group` but never `group_position`, so
  `MediaController.php:762` stores `0` for every item; the app then reads galleries via the

  upload order.**

  moderated site a member's own pending upload vanishes from "my library" with no explanation.

  `onPress`: a failed block gives the user nothing at all.
- **Pro is the unguarded half of a lockstep pair:** `v2.3.1` tag missing entirely (13 source

- **The release smoke gate passes on skips.** `qa/.last-smoke-pass.json`: fresh-install 0/0/5,
  upgrade 0/0/3, cross-browser 0/0/4. `pass:0 fail:0` reads as green, so a release can ship
  having never been install- or upgrade-tested.
- `components/LayoutFeeds.tsx:379,435` — Instagram and Dribbble feed layouts have **no error
  state** (Dribbble also has no empty state and no pull-to-refresh), while the comment at
  `:76-79` claims that exact bug was fixed. `components/MediaFeedGrid.tsx:51-59` renders
  "Pull to retry" **before** the FlatList, so there is nothing to pull.

## Suggested sequencing

1. Messaging poll N+1 (load-driven; the only one that can fall over today).
2. `album-viewer` + `BaseBPTabIntegration` prefetch, and paginate `AlbumService::get_items()`
   (`get_item_count()` already exists and is unused by the templates that `count()` instead).
3. App offline layer: `NetInfo` + `onlineManager`, `defaultOptions.mutations.retry`, an
   `ErrorBoundary`. One change closes a whole class.
4. A shared `hooks/cacheKeys.ts` (`AFFECTED_BY_MEDIA_CHANGE` / `AFFECTED_BY_AUTHOR_CHANGE`)
   consumed by every mutation — `optimisticCache.ts` solved the entity-flag half of this class;
   the list-membership half has no owner, which is why each mutation misses a different subset.
5. Pro CI + the missing `v2.3.1` tag. Every gate Free passes is currently being read as covering
   both halves of the pair.

## What is already right (templates for the fixes above)

Correct implementations of every pattern above already exist in-tree: pagination + real
`COUNT(*)` + batch hydration in the Pro Compete trio (`BattleService::prime_battle_caches():707`,
`TournamentService::prime_participant_counts():999`, `ChallengeService::prime_entry_counts():851`
behind `Admin/AdminPagination.php:41`); shared WHERE so list and count cannot drift
(`MessagingService::conversation_tab_where()`, `MediaRepository::build_query_parts()`);
keyset-cursor cron with per-run caps (`ViewRetentionService::purge():50`); the 1.7.0 grid
prefetch in `MediaController::get_items()`. The defects are the screens that never got the
treatment, not missing knowledge.
