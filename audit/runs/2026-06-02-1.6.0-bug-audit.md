## REAL bugs — confirmed defects (13)

### High severity (6)
1. **Unable to optimize image / "headers already sent"** (free, #9936976275) — `Admin/MediaListPage.php:25,53,59`: `handle_bulk_actions()` runs inside the `render()` submenu callback (after headers sent), then `wp_safe_redirect()`+`exit` at 736-749 → warning. **Fix:** move `handle_bulk_actions()` to the `load-{page_hook}` action (fires before output).
2. **Users unable to create albums (Duplicate entry '' for slug)** (free, #9937288527) — `Repository/MediaRepository.php:600-607`: `set()` INSERT for a new index row leaves `slug` at DEFAULT `''`; `mvs_media_index` has `UNIQUE KEY slug`. 1st album inserts `slug=''`, every later album collides → silent fail, privacy/album_type lost (reads back public). **Fix:** in `AlbumService::create()` write privacy + a unique slug via `set_many()` in one INSERT.
3. **Privacy settings not working for Albums** (free, #9941259516) — `Integrations/BuddyPress/BaseBPTabIntegration.php:428` `render_albums_grid()` renders every album with **no** `can_view()` gate; `single_album_content():217` checks only author match. REST `AlbumController` gates correctly (253/279) but the BP template path is ungated. (Privacy IS persisted — distinct from #9937288527.) **Fix:** add `PrivacyService::can_view()` checks in `render_albums_grid()` + `single_album_content()`.
4. **[PRO] Assets not enqueued on shortcode pages** (pro, #9941413137) — `Blocks/Shortcodes.php:166-238`: `render_*_feed()` never calls `enqueue_assets()`; `LayoutManager::enqueue_assets():190-213` `is_mvs_page` gate excludes shortcode-only pages. Feeds render unstyled + dead JS. Leaderboard same class (medium). **Fix:** call `$layout->enqueue_assets()` in each shortcode renderer.
5. **[PRO] MemberPress memberships not mapping** (pro, #9941630153) — `Integrations/MemberPress/QuotaAdapter.php:151`: `get_posts(post_type=>'memberships')` but MemberPress CPT slug is `memberpressproduct` → always empty → mapping UI unusable. **Fix:** change to `memberpressproduct`.
6. **[Pro] Flickr site-default key option mismatch** (pro, #9945274050) — `Integrations/Flickr/Connector.php:41` `META_PREFIX='mvs_connector_flickr_'` reads `mvs_connector_flickr_app_key/secret`, but `ProSettings.php:262/283` saves `mvs_pro_connector_flickr_*` and `Migrator` RENAMED_OPTIONS_V1 deletes the legacy key → `has_default_credentials()` always false, one-click connect dead. **Fix:** add an `OPTION_PREFIX='mvs_pro_connector_flickr_'` for option reads (keep user-meta prefix unchanged).

### Medium severity (4)
7. **Upload starts immediately, no metadata pause** (free, #9936816170) — `src/blocks/media-upload/view.js:146-157`/`133-145`: `handleFileSelect`/`handleDrop` call `uploadFiles()` instantly; metadata fields are present but never gated. **Fix:** stage files to `ctx.pendingFiles`, show a metadata step, upload only on explicit submit.
8. **400 on deleting messages** (free, #9936826065) — `Messaging/MessagingService.php:984-1000`: `delete_message()` WHERE `id AND sender_id` → recipient delete affects 0 rows → returns false → `MessagingController.php:539` maps to 400. Recipients can never delete; also non-idempotent. **Fix:** per-participant `deleted_for` (or allow recipient soft-delete) + treat 0-rows-already-deleted as 200.
9. **Friends/groups privacy options missing on frontend** (free, #9937856491) — upload/edit selects in `templates/partials/shared-ui-frame.php:231,319` + `dashboard-content.php:378` render only public/members/private; admin (`MediaListPage.php:214`) and backend accept friends/group/custom. **Fix:** add `friends` (gate on `bp_is_active('friends')`) + `group` options to those selects.
10. **[PRO] Default package assigned to existing users** (pro, #9941320629) — `Quota/QuotaService.php:211-217`: `get_user_package()` falls back to `get_default_package()` at read-time for **every** user with no package meta, not just new ones; no `user_register` hook. **Fix:** assign default on `user_register` only; keep read fallback but don't treat it as "assigned."

### Low severity (3)
11. **AI settings link redirects to wrong tab** (free, #9941190178) — `Admin/StatsPage.php:477` links `?page=mvs-settings&tab=ai`, but `settings-nav.js:44` is hash-only (no `?tab` handler) → lands on General. **Fix:** change link to `...#ai`.
12. **CSV export fputcsv deprecation** (free, #9941334783) — `Admin/StatsPage.php:92,95`: `fputcsv()` missing the 4th `$escape` arg (PHP 8.1+ deprecation, fires every export). **Fix:** pass `''` as 4th arg.
13. **Moderation tab UI broken on mobile** (free, #9941822952) — `assets/css/admin.css:2014` `.mvs-admin-tabs` flex with no wrap/overflow; `.mvs-moderation-table:1914-1919` no `@media`. **Fix:** `flex-wrap:wrap`+`overflow-x:auto` on tabs; `@media(max-width:640px)` to collapse table columns.

## Works as designed (2) — recategorize, don't "fix"
- **Cannot unselect ALL allowed file types** (free, #9941178994) — `Sanitizers.php:121-123` deliberately ignores the all-empty case (prevents disabling all uploads). Partial unselect works. **Action:** optional UX notice; close as WAD.
- **Re-import demo data after delete** (free, #9948789971) — capability already ships: `cleanup-demo-data.php:218-219` invalidates the overview cache so the Import button reappears when media count hits 0 (`OverviewPage.php:253-280`). *(adversarial verifier overrode the first reviewer's ENHANCEMENT label — already-shipping, not missing.)* **Action:** if Import doesn't reappear it's a cache issue; otherwise close as WAD.

## Enhancements (3) — feature requests, not bugs (move to a backlog/feature list)
- **Add media to manual collections w/ picker** (free, #9937408893) — backend complete (`FavoriteService::toggle($collection_id)` + REST arg) but **no frontend picker UI**; all `/favorite` POSTs omit `collection_id`. Build a YouTube-style collection-picker modal.
- **Notifications header sticky on scroll** (free, #9937212197) — `frontend.css:3462` header lacks `position:sticky` (parent is the scroll container). One-line CSS add.
- **DM access + online-status as user-level settings** (free, #9937280163) — read path is user-aware (`MessagingService.php:85-88` reads `_mvs_dm_access`) but no profile UI/REST to set it; online status is global-only. Add fields to `PUT /me/profile`.

## Bonus bug found by the sweep (not a card — file it)
- **Webhook HMAC secret blanked on every save** (free, **high**) — `Admin/Settings/Sanitizers.php:176-180` stores `secret = sanitize_text_field($webhook['secret'])`, but `FieldRenderer::render_webhook_field():447-453` renders the secret input empty with "leave empty to keep" hint. Every save writes `''`, silently breaking signature verification. **Fix:** preserve existing secret when submitted value is empty (mirror `Sanitizers::sanitize_password_option():134-141`).

### Other sweep notes (low / confirm-intent)
- Album list `X-WP-Total` (`AlbumController.php:260`) reports unfiltered `found_posts` while body is privacy-filtered → minor count info-leak (a logged-out user can infer private-album count). MediaController does not have this.
