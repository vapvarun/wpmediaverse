# Security review - WPMediaVerse Free + Pro 2.6.4

Date: 2026-11-12. Diff reviewed: `v2.6.3..2.6.4` in both repos. Verdict: **PASS** (Critical 0, High 0, Medium 0, Low 0 new).

## G1 - mechanical sweep (`security-sweep.sh --baseline v2.6.3`)

No CRITICAL pattern in own code, in either repo. Pro: every count equals v2.6.3. Free: every count equals v2.6.3 except `cap-own-scope-as-authority`, which fell from 5 to 3 (the album and collection capabilities are now the manager capability, not an own-scope one).

## G2 - authorisation matrix

`audit/route-authority.json` + `tests/unit/RouteAuthorityTest.php` (Free and Pro) pass in the full suites on the 2.6.4 head: Free 939 tests, Pro 756 tests, 0 failures. The new `tests/unit/AlbumAdminScreenCapTest.php` pins that an editor cannot edit or open a member's album or collection in wp-admin and that an administrator can create and publish one.

## G3 - scoped review of the diff

Read: album and collection capability mapping (`PostTypes/Album.php` `manager_capabilities()`, `Collection.php`), the Stories REST controller and service in Pro (`StoryController`, `StoryService`), the Stories role setting (`Sanitizers::sanitize_stories_post_roles`), and demo seeding and cleanup.

### Findings

| Sev | Location | Note | Status |
|---|---|---|---|
| FIXED | Free `PostTypes/Album.php`, `Collection.php` | Editors held `edit_others_posts` and `delete_others_posts`, so an editor could edit or delete a member's album or collection in wp-admin and over REST. Edit and wp-admin write capabilities now map to `manage_mvs_settings`; deleting over REST is allowed to the owner and holders of `moderate_mvs_media` (by design, moderators remove content), which a default Editor holds. Browser walk confirmed: editor PUT 403, editor DELETE 204. | Fixed in 2.6.4; REST delete by moderators unchanged in intent |

No new finding. Checked and safe:

- `POST /mvs/v1/stories`: the owner check runs first, then the Post stories capability. Taking a story down stays with the owner check.
- `story_only` deletes the item when the story ends, so it is honoured only for someone who may delete that item (`can_edit_media` with the delete capabilities).
- A client may ask for a shorter story than the owner's Story length, never a longer one.
- The Seen by list and reaction tally are returned by the viewers route, which allows only the story owner and site managers.
- `post_mvs_stories` is granted to every upload-capable role on update, so no site loses Stories, and the owner narrows it per role. It is declared as a feature capability in `audit/capability-map.json`.

### Flagged by scanners but safe

The scanner patterns are unchanged from 2.6.3 (interpolated SQL on table names, `readfile` in the signed serve path, own-scope capability checks paired with ownership comparisons). No new instance was added by this release.
