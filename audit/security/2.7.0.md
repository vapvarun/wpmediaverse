# Security review - WPMediaVerse Free + Pro 2.7.0

Date: 2026-11-24. Diff reviewed: `v2.6.4..2.7.0` in both repos. Verdict: **PASS** (Critical 0, High 0, Medium 0, Low 0 new). One security fix ships in this release (G3).

## G1 - mechanical sweep (`security-sweep.sh --baseline v2.6.4`)

No CRITICAL pattern in own code, in either repo. Counts that changed against v2.6.4, each read:

- `sql-direct-interpolated`: Free 55 to 64, Pro 27 to 30. Every new instance is in `uninstall.php`: the batched Action Scheduler, post, postmeta and term-relationship deletes interpolate id lists that are `array_map( 'intval', ... )` of a prepared SELECT, and the comment deletes use fixed literals (`'mvs_comment'`, `'mvs_media_id'`). No request data reaches them.
- `no-abspath-guard`: Free 7 to 20, Pro 3 to 14. The new files are developer tooling that never ships (`bin/lib/extension-guard-check*.php`) and the untracked QA handoff folder under `docs/`; `docs/` and `bin/` are excluded from both zips (`.distignore`).
- The one new `unserialize` in the diff is upstream Action Scheduler 4.0.0 (`libs/action-scheduler/classes/data-stores/ActionScheduler_DBStore.php`), vendored and not patched here.

All other counts equal v2.6.4.

## G2 - authorisation matrix

The authority manifests (`audit/route-authority.json`, `capability-map.json`, `render-authority.json`, `admin-action-authority.json`) and their tests pass on the 2.7.0 head: Free 26 tests, Pro 20 tests, 0 failures (`RouteAuthority`, `CapabilityAuthority`, `RenderSurfaceAuthority`, `AdminActionAuthority`, `AlbumAdminScreenCap`, editor-moderation tests).

## G3 - scoped review of the diff

Read: `Capabilities/MediaCapabilities.php` (role caps, `EDITOR_MODERATION_CAPS` and the upgrade that strips them), the new and changed `current_user_can()` gates (housekeeping notice `update_plugins`, Pro activation and licence screens `activate_plugins`, Free Reports screen `manage_options`), the batched uninstall deletes in both plugins, and the Pro Documents manage-cap removal on uninstall.

### Findings

| Sev | Location | Note | Status |
|---|---|---|---|
| FIXED | Free `Capabilities/MediaCapabilities.php` | A plain WordPress Editor held `moderate_mvs_media`, `manage_mvs_access` and the others/private media caps, so a blog editor could moderate and edit any member's media. Editor now gets the same own-media caps as Author; a one-time migration (`Migrator` calls `strip_editor_moderation()`) removes them from the stored editor role and from the saved Permissions matrix. Owners grant moderation per role in Settings > Permissions. | Fixed in 2.7.0, called out in the Upgrade Notice |

No new finding. Checked and safe: every new capability gate uses a site-level capability; the uninstall id lists are integer-cast; no new `wp_ajax_nopriv_`, REST route or `__return_true` permission callback was added.

### Flagged by scanners but safe

Unchanged from 2.6.4 apart from the G1 items above (interpolated SQL on table names, `readfile` in the signed serve path, own-scope capability checks paired with ownership comparisons).

## G4 - external scanner

WP Vanguard was not available in this environment, so it was **not run**. Recorded as not run, not as a pass.

## Plugin Check on the built zips

Run on the installed 2.7.0 zips (WordPress 7.1.5, PHP 8.5) and on the v2.6.4 distributable trees in the same stack, errors only, own code compared by file, sniff and message. Vendored libraries counted separately and never patched.

- Free: 114 own-code errors, 0 new against v2.6.4 (314 in Action Scheduler and the EDD SDK).
- Pro: 34 own-code errors, 0 new against v2.6.4 (2 in the EDD SDK).

The first run found 3 new Free errors and 1 new Pro error, all on queries that were already safe (a translators comment on Action Scheduler's own string, and `NotPrepared` on integer id lists and fixed SQL fragments whose suppression named the wrong sniff or sat on the wrong line). Fixed in 2.7.0 with comment-only changes. The inherited errors stay on the Bugs board with the other inherited gate failures.

## Gate E - reachability and OpenAPI tooling: waived for 2.7.0

Owner decision, 2026-11-24. MediaVerse does not yet have the route reachability and OpenAPI comparison tooling Gate E expects, so the gate was not run for this release. The route authority test (G2) still fails the build when a route loses its permission check, so the waiver covers drift detection, not authorisation. Follow-up: port the reachability/OpenAPI tooling next version (Bugs card proposed in the release report).
