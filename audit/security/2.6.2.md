# Security review - WPMediaVerse Free + Pro 2.6.2

Date: 2026-10-13. Diff reviewed: `v2.6.1..2.6.2` in both repos. Verdict: **PASS** (Critical 0, High 0, Medium 0, Low 3 recorded).

Earlier in the cycle, per-commit reviews raised two issues that were fixed before this pass: the `group` filter on `GET /media` listed private and hidden BuddyPress groups to non-members (now `MediaRepository::group_scope_clause()` answers `1 = 0` unless the group is public, the viewer is a member, or has `bp_moderate`), and a mixed-privacy BuddyPress post was briefly made public (reverted to the strictest rule; the per-item rebuild is planned for 2.7.0). A third, an edited comment leaving its old wording on the activity post, is fixed by removing the copy on edit (`ActivitySyncIntegration::remove_mirror_on_edit()`).

## G1 - mechanical sweep (`security-sweep.sh --baseline v2.6.1`)

No CRITICAL pattern in own code, in either repo. Pro: every count equals v2.6.1. Free: `sql-direct-interpolated` 52 -> 55 and `no-abspath-guard` 5 -> 6. The three SQL lines are new `Migrator` index statements whose table and column names are code literals (`mvs_media_meta`, `mvs_messages`, `media_id` / `attachment_id`); the unguarded file is `bin/lib/code-standard-check.php`, a CLI dev script that `.distignore` keeps out of the zip. `cap-own-scope-as-authority` went down 6 -> 5.

## G2 - authorisation matrix

`audit/route-authority.json` + `tests/unit/RouteAuthorityTest.php` (Free and Pro) pass in the full suites run by `bin/local-ci.sh` on the 2.6.2 head. Live GET probes as a Subscriber (`qa_attacker`) and a visitor on the Docker QA site: `group=1` returned an empty list; another member's private item, a DM item and a private gallery cover all returned 404 on `/media/{id}/group`; a mixed gallery returned only its public items; the messaging poll for a conversation the prober is not in returned no typing or presence and `/conversations/2/messages` returned 404.

### Flagged by scanners but safe

- Interpolated SQL in `group_scope_clause`, `gallery_rows`, `gallery_tile_counts`, `mark_notifications_read_from`: the alias is limited to `[a-z_]`, tables come from `$wpdb->prefix`, every value is a placeholder.
- `get_group_items` with `__return_true`: public on purpose, gated by `can_view` with a 404 (same accepted pattern as 2.6.1).
- `wp_delete_comment( ..., true )` in a loop: reaches only children of a comment the actor may already delete.
- `finfo_file` without a close: the handle is freed automatically; the MIME type is still checked against the allowlist.
- Pro `libs/edd-sl-sdk/src/Utilities/Path.php`: now `plugins_url()` instead of a URL built from `HTTP_HOST` and `DOCUMENT_ROOT`, which removes a host-header-controlled asset URL.
