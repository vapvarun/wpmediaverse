### Flagged by scanners but safe

- `{$mvs_col}` in the favorites SQL is always the literal `user_id` or `collection_id`.
- `held_only_by()` builds `{$in}` from `%d` placeholders, and `{$live}` is prepared.
- The `MessagingService::batch_unread_counts` UNION inlines only the table name; every value goes through `prepare()`.
- The comment edit and delete and the reaction delete are login-only routes, but ownership is checked in the handler.
- `connectors/{id}/prefs` writes only the caller's own user meta. The connector id and values are both checked against allowlists.
- The unsubscribe GET link is signed with HMAC-SHA256 (`wp_salt('auth')`, `hash_equals`) and can only turn emails off.
- `auth/app-password` is exempt from the members-only gate but still needs the password and has two rate-limit layers.
- The `MVS_CSS` `sprintf` values are all allowlisted or pattern-checked, which closes the old stored-CSS break-out.
- The `StorageService` host suffix match applies only to URLs the server wrote, and refuses backslash and userinfo.

### Tightened in this release

- Hidden items now answer 404 instead of 403.
- `can_view()` refuses drafts and trashed items to anyone but the owner.
- A replaced file goes through the upload size check.
- The signed-URL lifetime is capped at one week.
- AI usage data needs `manage_mvs_settings`.
- Folder rename, move, trash and delete need MANAGE rights.
