## G3 - scoped review of the diff

Read each security-relevant change:

- `MessagingService::may_create_group()` and the `mvs_can_create_conversation` filter: a filter can only deny. The size cap still applies first. No new input is trusted. Pro's group route returns 403 when it refuses.
- `mvs_message_content_check` now also runs for attachment-only sends, with an empty text. It can only add a refusal; `sender_may_attach()` still runs first.
- `MediaTypes::canonical_mime()` maps `video/quicktime` to `video/mp4`. The type is still SNIFFED from the file content (finfo), never taken from the extension or the browser. The mapping applies only while the owner allows `video/mp4` and WordPress itself lists `video/quicktime` in `get_allowed_mime_types()`. A text file renamed `.mp4` is refused (checked in the browser smoke). PDFs and unrecognised types are still refused by `reject_unsupported_mime()`.
- `UploadService::allows_quicktime()` / `client_mimes()` / `accept_attribute()`: client-side hints only; the server check above is the enforcement.
- `CloudOps::actionable_row( $id, $with_trashed )`: a trashed row is visible only to a cloud-to-local move. An upload to the cloud still refuses it (test: `test_a_trashed_photo_is_brought_home_but_never_sent_to_the_cloud`). `MediaFileRotator::take_down()` queues the existing repatriation job on rejection, flag and trash, which removes the CDN copy: it narrows exposure, it does not widen it. It runs from existing moderation and trash hooks and adds no new entry point.
- `MediaRepository::tag_cloud()` / `tag_cloud_total()` with `$author_id`: the author id is bound through `$wpdb->prepare()` as `%d`; the privacy clause is the public-only clause, so a profile never lists a tag used only on private media.
- `CollectionController::update_item()`: refuses an empty title (400), same as create. No capability change.
- Pro `Shortcodes::missing_id_notice()`: shown only to users who can `edit_posts`, output escaped with `esc_html` / `esc_attr`. The shortcode example is built from a fixed tag name.
- Front-end JS (`dashboard-view`, `shared-ui`, `profile-actions.js`, `instagram.js`): `apiWrite()` only turns a non-OK response into a thrown error; the follow sync event carries a numeric user id and renders text with `textContent`.
