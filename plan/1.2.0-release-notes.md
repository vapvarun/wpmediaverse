# WPMediaVerse 1.2.0 — Release Notes (canonical)

> Mirror of the 1.2.0 entry in `readme.txt`. This file is the source-of-truth
> for the release announcement copy, blog post, store changelog, and email
> notification. `readme.txt` Changelog stays terse; this file carries the
> long-form context the support team uses when customers ask "what changed?"
> Pairs with Pro's `../wpmediaverse-pro/plan/1.2.0-release-notes.md`.

## Headline (60 seconds for the support team)

1.2.0 is the **completion release** for everyone using WPMediaVerse as a
photo / media community. Two new blocks (`Member Photos`, `PDF Viewer`),
sortable Media Grid, search autocomplete on Explore, lightbox Download +
share endpoint, per-media Edit modal with privacy / allow-download / opt-in
slug change, Open Graph + Twitter Card meta on every single-media page,
admin Bulk Actions (Trash / Restore / Delete-permanently), Chat Panel
visibility setting, and a 6-reaction WCAG 2.1 AA accessibility pass. Plus
~12 customer-visible bug fixes — most surfaced during the Playwright QA
walkthrough that closed out the milestone.

## What's new — frontend

### Member Photos block + shortcode (`mvs/member-photos`, `[mvs_member_photos]`)

Auto-detects whose photos to show: explicit `userId` → BP displayed user →
post author → current user. Drop into a BP profile, an author template, or
a regular page and it just works. Hero card layout: 96 px avatar (with
gradient initials fallback when Gravatar is unreachable), display name +
@handle + bio + stats (Photos / Followers / Following) + View Profile +
Follow / Following toggle (logged-in viewer only, with `aria-pressed`).

Container-query responsive: switches to a vertical stack at <520 px
container width — so the same block reads well in a sidebar widget AND a
full-width FSE template part. Below 320 px (typical 240–280 px sidebars)
the layout compacts further.

### PDF Viewer block + shortcode (`mvs/pdf-viewer`, `[mvs_pdf_viewer]`)

Embeds PDFs uploaded via WPMediaVerse using the browser's native PDF
viewer (`#view=FitH` URL fragment). Inspector exposes height (200–1400 px)
and toolbar toggle. Five distinct empty states (no id / not found /
not a PDF / no permission / asset missing) — never a blank rectangle.

### Sortable Media Grid

Four new `orderBy` options on `mvs/media-grid` and `[mvs_gallery]`:
`popular`, `views`, `reactions`, `random`. Asc / desc direction toggle in
the inspector (hidden when sort = random). New `userId` attr on the block
and `user_id` attr on the shortcode let you filter to one author —
useful for "this user's recent uploads" widgets.

### Search autocomplete on Explore

Type two characters and a dropdown of up to 8 title matches opens
(debounced 250 ms). Full keyboard support: ArrowDown / ArrowUp navigate,
Enter selects, ESC closes. `AbortController` cancels in-flight requests
when a newer keystroke arrives so a slow first response can't overwrite
fast second-keystroke results. ARIA combobox + listbox semantics for
screen readers.

### Lightbox: Download + Share endpoints

New `Download` toolbar button next to Share + Open. Each download writes
a row to `mvs_media_views` with `event_type='download'` and increments
`mvs_media_stats.downloads`. Rate-limited at 30 / minute / user via the
central `RateLimiter`. New `POST /mvs/v1/media/{id}/download` REST
endpoint. Same shape for the new `POST /mvs/v1/media/{id}/share` endpoint
that increments `mvs_media_stats.shares` and fires the
`mvs_share_recorded` action.

### Per-media Edit modal

Click the Edit button on your own dashboard cards (or the cog inside the
lightbox) to change title, description, privacy, allow-download, and the
URL slug for one media item. `PUT /mvs/v1/media/{id}` accepts
`allow_download` (boolean) and a new `slug` parameter. The `slug` field
is opt-in via the **"Update URL slug"** checkbox — title edits leave the
URL stable by default. When the user opts into a slug change AND they're
viewing the old URL, the page redirects to the new permalink so
reload doesn't 404.

### Open Graph + Twitter Card meta

Every `/media/{slug}/` page now emits `og:title`, `og:type`, `og:url`,
`og:site_name`, `og:description`, `og:image` (signed URL), and
`og:image:alt` plus `twitter:card=summary_large_image` and the
matching twitter title / description / image meta tags. Paste a media URL
into Slack, Twitter, LinkedIn, Discord, or any other unfurl-aware client
and the rich preview renders correctly.

### Upload modal polish

Preview tiles now show the filename and a per-tile (×) remove button so
multi-file uploads are easier to manage. Audio files render with an
audio-fallback icon (no broken-image SVG). Top-8 popular tag pills
appear below the tags input — click to append (de-duped silently).

## What's new — admin

### Bulk Actions on All Media

Multi-select header / footer checkboxes + a Bulk Actions toolbar above
the media list. The action menu is context-aware to the current filter:
in the Trash filter you get **Restore** + **Delete permanently**;
otherwise you get **Move to Trash**. `wp_nonce_field('mvs_bulk_media',
'mvs_bulk_nonce')` + capability gate on every submit; success notice
shows the count + action.

### Chat Panel visibility

New setting under Settings → Direct Messages → "Chat Panel Visibility":
Everywhere (default) / WPMediaVerse pages only / BuddyPress pages only /
Disabled. The `mvs_should_render_chat_panel` filter wraps the resolved
decision so themes / plugins can fine-tune by URL pattern (the second
filter argument is the resolved visibility setting).

### Global "Allow downloads" toggle

Setting under Settings → Media Display. Single switch hides the new
lightbox Download button site-wide AND makes the `record_download` REST
endpoint refuse with a 403 + `mvs_downloads_disabled` error code. Per-
media `allow_download` meta still gates further when the global is on.

## Accessibility (WCAG 2.1 AA pass)

- **6-reaction lightbox bar** — Like / Love / Haha / Wow / Sad / Angry
  each carry sentence-form `aria-label` and `aria-pressed` toggles; emoji
  spans are `aria-hidden`; the wrapper is `role="group" aria-label="Reactions"`.
- **Lightbox toolbar** — every button (Favorite / Share / Download /
  Open / Report) gains an `aria-label`; `:focus-visible` outlines on
  `.mvs-lightbox-action / -close / -nav` so keyboard nav is visible.
  The toolbar fits 5 buttons evenly via flex:1 + space-between; no
  horizontal scroll at desktop or mobile.
- **Block render forms** — explore-feed search, media-upload file input,
  privacy select, title / description / tags inputs all gain `aria-label`
  (placeholder ≠ label per WCAG).
- **Search-mode tab toggle** on `templates/explore.php` gains
  `role="tablist"` + `role="tab"` + `aria-selected` semantics.
- **BuddyPress notification dedup** — when BP is active, MVS notifications
  mirror to BP's nav bell only (not also rendered in the dashboard).

## Important fixes

- **Title edit no longer changes the URL slug**. The previous behaviour
  silently regenerated the slug on every save, breaking inbound links and
  search-engine cache. Slug now stays stable; admins can opt into a slug
  change via the new "Update URL slug" checkbox in the Edit modal and on
  `/media/{slug}/`. Page redirects to the new URL on slug change so the
  old URL doesn't 404 on reload.
- **BuddyPress activity duplicate image fix**. A Phase 8 linkage code
  path was appending its rendered grid even when the activity content
  already contained the inline grid markup, so every composer-posted
  activity rendered each image twice. Fixed by reordering the render
  filter — inline content is authoritative; linkage is the fallback for
  empty content.
- **Author profile URLs no longer leak BP mention HTML**. Five sites
  built `/media/@user/` URLs inline; BP's at-name filter then rewrote
  the `@user` substring into mention HTML, corrupting the URL into
  `/media/<a class='bp-suggestions-mention' …>@user</a>/`. All five
  routed through `TemplateHelpers::get_user_profile_url()`.
- **Lightbox toolbar fits 5 buttons on one row**. Earlier 1.2.0 builds
  used `display: flex` + `margin-left: auto` on the Report button which
  pushed the toolbar past the 380 px sidebar bounds. Distributing via
  `flex: 1` + `space-between` fits at every viewport.
- **Moderation webhooks fire reliably** — listeners were registered on
  `mvs_media_moderated` but the firer used `mvs_moderation_changed`.
  Affected since 1.0.0. All listeners renamed.
- **`mvs_reaction_removed` and `mvs_share_recorded` actions now fire**
  so cache invalidation listeners catch un-react and share events.
  Without these, stat caches lagged by the cache TTL.
- **Search autocomplete race condition** — keystrokes weren't aborting
  in-flight requests, so a slow first response could overwrite a fast
  second response. Now uses `AbortController`.
- **DM access dropdown** (Settings → Social → "Who can send me direct
  messages") no longer silently reverts "Nobody" / "Mutual followers
  only" to "Everyone" on save. After upgrading, please reopen Settings →
  Social and confirm your preferred access — the dropdown now reflects
  the saved value byte-for-byte. Affected since 1.1.0. Commit `d986525`.
- **Demo data importer fully working** — `seed-demo-data.php` was
  calling `MediaRepository::*` static-style; the repository is a
  container service. All 14 call sites swept. Demo seeder now produces
  50 media + 5 demo users + 5 albums + 159 reactions cleanly.
- **`AlbumService::create()`** added — single source of truth for album
  creation. `AlbumController::create_item` now delegates.
- **`PUT /media/{id}` `allow_download`** flag now reads from any body
  encoding (was JSON-only).
- **Stats block fits on narrow phones** — switched to
  `minmax(min(180px, 100%), 1fr)` track formula and stacks single-column
  below 480 px.

## Architecture

- **`Core\SettingsHelper`** — canonical static accessor for paired-plugin
  settings reads. Pro and themes must use this instead of direct
  `get_option('mvs_page_*')` reads (Free invariant A4).
- **Block standard alignment (Phase 7)** — Free's 9 registered blocks
  share the same Spacing / Border / Shadow / Visibility inspector panels
  as Pro and wbcom-essential. Per-instance scoped CSS via
  `MVS_CSS::add()` keyed off `mvs-block-{uniqueId}`.
- **`BaseBPTabIntegration` extracted** (Phase 5 P2.4) — Profile + Group
  BP tab classes shared ~80% of method bodies; now consolidated. Single
  bug fix on either propagates to both. Net delta -109 lines.
- **`SettingsContractTest`** — `register_setting` whitelist drift caught
  at unit-test time, not customer save-time.
- **`mvs_should_render_chat_panel` filter** now passes the resolved
  visibility setting as the second argument so callbacks can scope their
  override by the admin's chosen mode.

## Coordination with Pro

Pro 1.2.0 pairs with this release. Customers running both plugins should
update both — Pro depends on the new `Core\SettingsHelper` (with a
graceful fallback for pre-1.2.0 Free) and the new block-standard
infrastructure (`StandardAttributes` + `MVS_CSS::add()`).
