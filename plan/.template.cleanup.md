## Phases

### Phase 1: Soft-remove with deprecation (this release)
- Mark each non-hard-removable symbol with `@deprecated since X.Y.Z`
- Add `_doing_it_wrong()` or `E_USER_DEPRECATED` trigger at runtime
- Add migration shim that calls the new implementation
- Ship in version X.Y.Z

### Phase 2: Hard-remove (1 major release later)
- Delete the symbol
- Document under `Breaking changes` in changelog
- Ship in version X.Y+1.0

## What this plan does NOT do

(Important — keeps scope tight; prevents the loop where each cleanup spawns more cleanup)

- Does not refactor surrounding code beyond what's strictly necessary to remove the listed symbols
- Does not change public API behavior for symbols left in place
- Does not move files between directories
- Does not rename anything

If any of those become necessary during execution, STOP, write a new cleanup plan, get it reviewed.
