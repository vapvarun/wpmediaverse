## Items

### 1. TIER-D — MediaRepository query builder + consumer migration

**Why deferred from 1.3.0:** several remaining direct-`$wpdb` call sites build dynamic SQL with conditional joins, NOT IN subqueries, and dynamic WHERE clauses. They don't fit the simple `count_by_X` / `query_by_X` helpers that landed in 1.3.0. A small query builder unblocks all of them at once.

**Scope:**

- **Design**: `MediaRepository::query(array $args)` builder
  - Filters: `status`, `moderation_status`, `author_id`, `search`, `tag_id`, `category_id`, `exclude_non_cover_group`, `limit`, `offset`, `orderby`
  - Output: array of media rows (same shape as `get_batch`)
  - Sister method: `query_count(array $args)` returning int

- **Refactor consumers** (8 files):
  - Free `templates/explore.php:340-368` — explore listing + count
  - Pro `templates/layouts/dribbble/feed-body.php`
  - Pro `templates/layouts/flickr/feed-body.php`
  - Pro `templates/layouts/pinterest/feed-body.php`
  - Pro `templates/instagram-feed.php`
  - Pro `templates/layouts/dribbble/profile.php` (gallery_exclude listing)
  - Pro `templates/layouts/flickr/profile.php` (gallery_exclude listing)
  - Pro `Integrations/{RtMedia,MediaPress,BuddyBoss}/MigrationAdmin.php` (admin-only, lowest priority)

**Estimated effort:** 6 hours (design + 8 consumer refactors + browser smoke)

**Risk:** medium. Query builder needs tests + SQL injection review. Each consumer needs browser-verify after migration.

**Acceptance:** `bin/cleanup-boundary-check.sh` returns 0 direct-`$wpdb`-on-Free-tables violations across both repos.

### 2. STORAGE-R2-DO — Cloudflare R2 + DigitalOcean Spaces support

**Why:** R2 has free egress (compelling for image-heavy community sites). DO Spaces is cheaper per-GB with a generous free tier. Both are S3-compatible — the existing S3 driver works for both with only the host pattern changing.

**Scope:**

- **Refactor `Integrations/AmazonS3/StorageDriver.php`**: extract `build_host()` + `build_endpoint_url()` as protected methods (currently the host pattern `{bucket}.s3.{region}.amazonaws.com` is hardcoded in 4+ places: `put_object`, `get_object`, `delete_object`, `head_object`).

- **`Integrations/CloudflareR2/StorageDriver.php`**: extends S3 driver. Overrides `build_host()` for R2's `{accountid}.r2.cloudflarestorage.com/{bucket}` pattern. Adds R2 account ID field. SigV4 with `region=auto`.

- **`Integrations/DigitalOceanSpaces/StorageDriver.php`**: extends S3 driver. Overrides `build_host()` for DO's `{bucket}.{region}.digitaloceanspaces.com` pattern. Adds region field (nyc3, ams3, sfo3, sgp1). Optional custom CDN field for `{name}.{region}.cdn.digitaloceanspaces.com`.

- **Settings UI**: 2 new cards in Storage tab. Mirror BunnyCDN's existing pattern (connection test, bucket auto-detect, credentials hidden on re-render, 2-step setup walkthrough).

- **Filter registration**: `add_filter('mvs_storage_driver', ...)` for both new providers.

- **Real-fixture testing**: upload + download + delete + signed URL on actual R2 + DO Spaces accounts.

- **Pro readme.txt**: feature announcement + admin walkthrough.

**Estimated effort:** 6.75 hours

**Risk gotchas:**
- R2: `region=auto` in SigV4 canonical request; path-style not virtual-hosted-style URLs
- DO Spaces: region in subdomain (not host) — SigV4 canonical needs the correct host header
- Test with real accounts — paid setup, not free trial

**Acceptance:** Settings UI lets admin connect, validate, and upload to both R2 and DO Spaces. Existing S3 + BunnyCDN flows unchanged.
